Vid2ArtCAD 标注管线

从 CAD 装配和关节定义出发，生成可回放的多视角运动视频及像素级部件标签，并通过质量门控整理成数据集。

当前主线产出的是合成真值（synthetic GT），不是人工画框，也不是视觉模型预测的 mask。

对视频中的每个像素，管线可以提供它属于哪个 CAD link；同时保存深度、部件可见性/轨迹元数据、相机参数和驱动运动状态。

核心流程

01 · 输入

CAD 装配

assembly.json、装配网格和部件 OBJ。

02 · 结构

规范运动学

Occurrence/link、关节 DOF、运动学树及闭环约束。

03 · 动作

轨迹与回放

生成 q(t)，求解闭环，并在 MuJoCo 中核对 FK。

04 · 影像

多视角渲染

输出同步 RGB 视频和逐视角相机标定。

05 · 标签

派生像素真值

Segmentation 映射到稳定 link ID，并导出深度与轨迹记录。

06 · 发布

验收与打包

校验视频、标签、运动学和 checksums，生成 manifest / split。

标注结果长什么样

samples/<asset>_multiview/
  rgb_cam01.mp4, rgb_cam02.mp4       # 多视角运动视频
  camera_cam01.json, camera_cam02.json
  motion.npz, timestamps.npy         # q(t)、link 位姿和时间戳
  labels/
    part_id_cam01/000000.png         # uint16 像素级部件 ID
    depth_cam01/000000.npz           # 压缩 float32 深度（key: depth）
    tracks_cam01.jsonl               # 每帧可见部件元数据
    ...                              # cam02 同理
    quality.json

part_id 编码：0 是背景，1..N 对应 link 顺序加一，65535 保留为 ignore。标签来自渲染器的几何分割结果，因此可与 CAD 部件及运动学状态对应。

关键组件

  • pipeline/fusion/：读取并适配 Fusion Assembly 源数据。
  • pipeline/kinematics/：关节规范化、运动学树、前向运动学及闭环求解。
  • pipeline/render/batch_tree_annotation.py：构建参考机构、生成轨迹并导出场景。
  • pipeline/render/multiview_annotation.py：生成第二视角视频、相机和多视角样本。
  • pipeline/render/labels.py：从 MuJoCo segmentation/depth buffer 导出标签。
  • pipeline/render/validate_sample.py 与 package_dataset.py：质量验收、校验和及 manifest 打包。
  • pipeline/render/auto_annotation.py：批处理入口，负责预览审核门禁、增量运行和失败分流。
来源边界：合成管线中几何标签是 synthetic_gt；运动幅度通常是管线策略值，不等同于真实机械行程。真实视频导入、SAM2/光流传播和 CoTracker 属于另一条扩展流程，传播结果是 pseudo，必须经人工逐帧复核后才能作为 human_reference 发布。

发布前检查

帧数与 FPS、双视角一致性、相机/几何范围、MuJoCo FK 误差、标签类型和尺寸、部件 ID 映射，以及样本文件 checksums。

运行入口

正式批处理：

python3 -m pipeline.render.auto_annotation \
  --data-root data/raw/batch_001 \
  --output-root output/annoation

预览需审核通过后，才会生成正式样本。

实现依据：docs/ANNOTATION_PIPELINE.md、pipeline/render/auto_annotation.py、labels.py 与数据集 manifest。
